# Progress and Blockers

## Progress tracking
The active ExecPlan is the primary detailed progress log.
Roadmap checkboxes should only be updated when behavior is implemented and verified.

After each milestone Codex should leave a concise record of:
- capabilities completed;
- commands/tests run;
- scenario evidence;
- architecture decisions made;
- known limitations;
- next milestone.

## Blocker format
When a user decision is genuinely required, report:
1. blocked acceptance criterion;
2. evidence/command output;
3. what was attempted;
4. local/mock fallback attempted;
5. smallest user input needed;
6. which unrelated work can continue.

Do not turn routine implementation uncertainty into a blocker.

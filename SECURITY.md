# Security Policy

Reliable Agent Lab intentionally contains mutating agent tools and fault-injection features. Treat these capabilities as potentially dangerous outside the controlled local demo environment.

## Supported environment

The repository is designed for:

- local development;
- Docker Compose-based demos;
- controlled CI environments;
- intentionally fault-injectable demo services.

It is **not** designed to control production infrastructure.

## Never commit secrets

Do not commit:

- LLM API keys;
- GitHub tokens;
- database passwords;
- private certificates;
- cloud credentials;
- `.env` files.

Use environment variables and `.env.example` placeholders.

## Tool safety

The project separates read-only tools from mutating tools.

Mutating tools must:

- have explicit schemas;
- operate only on allow-listed demo targets;
- have bounded behavior;
- expose clear errors;
- support idempotency where appropriate;
- require human approval when classified as high-risk.

Do not add:

- unrestricted shell execution;
- arbitrary SQL mutation generated by an LLM;
- arbitrary host command execution;
- direct production credentials.

## Vulnerability reports

If this becomes a public project with external users, add a private GitHub Security Advisory workflow and a maintainer contact here.

Until then, avoid publishing exploitable issues that affect real third-party systems.
